# Spec — Token usage optimization for downloaded Claude Code (work setup) (2026-08-01)

## L0 (required)

**Goal:** Cut Claude Code token spend on the operator's work-machine install (a vanilla "downloaded" Claude Code CLI, not this sharekit-profile harness) via model routing, context/cache hygiene, and a scoped tool-reduction layer — without degrading ability to work.

**User:** Lucas Santana, running a resource-constrained startup — token cost is a real budget line, not an abstraction.

**Why now:** Reported symptom is "burning way too many tokens and not being able to work properly" on the work machine. This harness (sharekit-profile / `~/.claude`) already has model-tiering, rtk, autocompact, and skill-listing-budget optimizations proven in production here (see Decision 1-2 below) — the work machine has none of that, so the fix is largely a port, not new invention.

**Success criteria:**
1. Work-machine `settings.json` sets explicit subagent model defaults (Haiku for mechanical, Sonnet default) — traces to Decision 1.
2. Work-machine CLAUDE.md/settings enable auto-compaction and set a sane trigger threshold — traces to Decision 4.
3. Work-machine has a documented, ranked short-list of context-reduction tools with a stated choice (not "try everything") — traces to Decision 5.
4. Baseline token/cost measurement exists for the work machine before changes (via `/usage` or OTel), so post-change savings are measurable, not asserted — traces to Decision 6.
5. Prompt-caching hygiene checklist applied to any custom system prompts/hooks on the work machine — traces to Decision 3.

**Constraints:**
- MUST: no bulk/batch agent work on uncached third-party providers (per user's existing global rule — provider rule in CLAUDE.md Model tiering section). Optimizations must stay on cache-capable Claude endpoints.
- MUST: this spec targets a **vanilla downloaded install** — do not assume rtk, custom hooks, or the sharekit-profile skill/agent library are present on the work machine unless the operator explicitly ports them.
- CAN vary: how much of the sharekit-profile harness gets ported vs. how much uses Claude Code's now-native built-in equivalents (compaction API, tool search/defer-loading) that didn't exist when rtk was first adopted (2026-07-09).

## Approach (L1)

1. **Baseline first** (D6): run `/usage` on the work machine for a few real sessions before touching anything — get the current per-session token/cost split by model and MCP server. Without this, "did it help" is unmeasurable.
2. **Model routing** (D1): add explicit `CLAUDE_CODE_SUBAGENT_MODEL=haiku` (or per-agent frontmatter) and confirm main-session default is Sonnet, not Opus, for routine work.
3. **Context hygiene** (D3, D4): trim CLAUDE.md to <200 lines; leave `autoCompactEnabled` on; set `effortLevel` to `medium` or `low` for non-architecture work; confirm cache TTL matches the auth method in use (subscription vs API key) and isn't being fought by a stale env var.
4. **Tool surface** (D5): audit configured MCP servers on the work machine, disable unused ones — this is higher-leverage than any listing-budget knob for a vanilla install.
5. **Re-measure** (D6 loop): re-run `/usage` after 1 week of the above. rtk and magic-compact/claude-rolling-context/token-optimizer-mcp are **rejected, not deferred** — JetBrains' controlled A/B (D2) found rtk net-negative-to-flat on actual session cost, and the alternatives carry the same unverified-claim risk rtk had before it was tested. Do not revisit unless one of them publishes an independent controlled benchmark.
6. **Correct this repo's own record** (separate from the work-machine port, but a direct consequence of D2): file a follow-up note/ADR addendum in sharekit-profile flagging that ADR-0008/ADR-0049's "keep rtk" decision was made on a metric (raw-byte compression) that JetBrains has since shown doesn't predict net session cost. Does not require reverting the hook immediately, but the decision record should not stand uncorrected.
