Mental model

How the pieces fit

Four layers. You invoke at the top; everything below runs to serve that intent.

1 · You invoke
Skills
One well-scoped task: /ship, /review, /verify. Runs in your context. Invoke with /name or let its description match your request.
Composites
A skill that auto-chains other skills with gates between phases (e.g. specify → plan → implement → verify). Prefer these: running sub-skills by hand skips the gates.
↓ dispatch
2 · Work gets done
Sub-agents
Autonomous workers in their own context (plus their own git worktree when 2+ writers share a repo). Analysis agents are read-only by construction; execution agents write. Run in parallel for independent work.
↓ wrapped by
3 · Hooks (automatic, every prompt & tool call)
Anchor the default modes · suggest a model tier · detect composites · block secret reads and risky git · keep analysis agents read-only · re-inject facts after compaction. You never call these: they fire on their own.
on a substrate of Standards Memory RAG index ADR vault CLAUDE.md
governed declaratively by .harness/ manifest.json mcp-policy.json README.md check-harness-manifest.sh

Security rules become diffable, CI-enforceable code: manifest.json holds sha256 fingerprints of security-critical config; mcp-policy.json declares MCP governance (defaultDeny, 17 dangerous-pattern regexes, call budget, timeout, approved servers). JSON is the source of truth: AGENTS.md mirrors it in prose, and scripts/check-harness-manifest.sh verifies fingerprints + policy invariants in CI.

Secret handling is layered. block-secret-reads.sh now guards the Grep tool too (a .env* glob or a credential directory such as ~/.ssh is blocked), and computer-use-guard.sh gates mcp__computer-use__request_access so desktop control cannot open a terminal, IDE or credential store around the other hooks. Both ship in hooks/ as opt-in bindings. Hooks stop accidents, not a determined exfiltrator, so pair them with deterministic permissions rules in your settings.json: deny on Read of credential paths (~/.ssh, ~/.aws, .env files) and ask on git push --force. The installer does not write those rules for you: --include-hooks merges only the hooks key.

Install · one command

Get the harness onto your machine

The harness ships as a sharekit profile. One command fetches it from github.com/LucasSantana-Dev/sharekit-profile, previews the changes, backs up anything it would overwrite, then copies claude/ → ~/.claude/. Prerequisite: Node ≥18 (for npx), or install the sharekit CLI via Homebrew / pipx (channels below). Hooks need only POSIX tools plus python3; jq is optional.

1
Preview first: see every change, apply nothing
$ npx @lucassantana/sharekit preview LucasSantana-Dev → lists files, counts, target paths · flags conflicts · zero writes
2
Install the profile: CLAUDE.md, skills, standards, agents
$ npx @lucassantana/sharekit install LucasSantana-Dev → backs up existing files · copies claude/ → ~/.claude/ ✓ 52 skills + 49 agents + 22 standards installed
3
Add the hooks: the automatic layer (gated for safety)
$ npx @lucassantana/sharekit install LucasSantana-Dev --include-hooks # hooks run shell commands under your account: review in preview first ✓ prompt, tool-call, subagent and compaction hooks wired

Hooks are flagged but not installed by default because they execute commands on every prompt and tool call. Review them in preview, then opt in: you get one confirmation, and only the hooks key is merged into an existing settings.json (sharekit 0.6.4+). The default set wires 8 bindings on 4 events; the other scripts in hooks/ are opt-in, bind the ones you want yourself.

4
Undo or update anytime
$ npx @lucassantana/sharekit rollback LucasSantana-Dev → restores the last backup $ npx @lucassantana/sharekit update LucasSantana-Dev ✓ syncs to the latest published version
prefer a CLI install? pick a channel brew install LucasSantana-Dev/tap/sharekit pipx install sharekit npm i -g @lucassantana/sharekit

Core concepts

Eight ideas that explain everything

Skill
A reusable, well-scoped workflow invoked with /name, or automatically when its description matches your request. Runs in your current context.
e.g. /review reads your diff → returns standards + spec findings.
Composite
A skill that auto-chains several sub-skills with a gate between phases. The composite-router hook emits 🎯 Composite match when your intent matches one. Always prefer it: running sub-skills by hand skips critical phases.
e.g. /three-man-team → architect → builder → reviewer.
Sub-agent
An autonomous Claude in its own context with a scoped toolset. Analysis agents (Explore, critic) are read-only by agentType: their tool set has no Write or Edit. Dispatch many in parallel.
e.g. the phase-runner agent spawns one agent per task, one wave at a time.
Hook
A shell script wired to a lifecycle event (session start/end, every prompt, every tool call). Fires automatically: exit 0 = silent, no overhead. You never invoke them.
e.g. on PreToolUse → block-secret-reads stops a Read or Grep of a .env file.
Standard
A policy doc the operator loads on demand: naming, testing, security, decision discipline. Standards are the "house rules" skills and agents follow.
e.g. code-standards.md, security.md, red-flags.md.
Model tiering
Match model strength to task. Fable for apex reasoning, Opus as fallback, Sonnet as the default for execution and mechanical work. Haiku is retired. A hook suggests the tier each turn.
e.g. a UserPromptSubmit hook suggests Sonnet for routine prompts, Fable for depth.
Autonomy
Default is proceed and report, not pause and ask. T0 reads and planning run silently; T1 branch commits and small edits proceed and report; T2 merges and architecture changes get one critic pass first; T3 destructive, production, money or outward publishes ask you.
e.g. "improve the tests" → it picks which tests & targets, then proceeds.
Default modes
Three modes are on by default: caveman (terse output that keeps every technical term verbatim), ponytail (lazy-senior coding discipline) and agent-econ (subagent token discipline). "stop caveman", "stop ponytail" or "normal mode" turns them off for the session.
e.g. "check-pr-automation-halt blocks force push → surfaced, not run."

Under the hood

What happens when you hit enter

Every prompt and tool call runs through the hook pipeline, silent on success. 35 shell scripts ship in hooks/; --include-hooks wires a safe default set (8 bindings on 4 events) and the rest are opt-in.

UserPromptSubmitEvery prompt. Warn when a long session gets expensive to keep (default) · opt-in: anchor the default modes, suggest a model tier, emit 🎯 Composite match if intent fits.
PreToolUseSafety gate. Halt on PRs with another person's comments, block force pushes and pushes to protected branches, surface stuck loops, scope memory writes (default) · opt-in: block secret reads on Read, Bash and Grep, protect secret files from edits, gate computer-use access.
SubagentStartIsolation. Analysis subagents must deny write and edit tools in their permission block, not just in the prompt (default).
PostToolUseObserve. Opt-in: a deterministic structural gate on skill edits and an async trajectory log.
PostCompactRecover. Re-inject the exact IDs, PR numbers and decisions saved before the compact (default).
Guardrails

Hard rules the operator won't break

Objective, non-negotiable. They override convenience and even composite behavior.

01Never automate a PR with another person's comments, or any open PR another person authored. Halt and tell the user. Bots (CodeRabbit, dependabot) don't count; check-pr-automation-halt.sh enforces it.
02Parallel for 2+ independent units: one Agent() per unit in one block (under 3 reads and 2 edits is exempt). A worktree is required only for write-capable agents when 2+ touch the same repo.
03Analysis agents use write-incapable types (Explore, Plan, critic, code-reviewer, security-reviewer). Prose "read-only" is not enough.
04No force merges or deploys through unclear CI or review state, and never echo or duplicate secrets.
05State-check before mutation: query current state first; if already satisfied, log "already done, skipping".
06Dispatcher is not executor: orchestrators do not implement logic-bearing changes. Trivial string or comment edits are allowed and logged as such.
07Repository is the source of truth: commit the context a future agent needs before acting on it.
08No big-bang rewrites without a gate: measure usage and build a 1-hour prototype first; more than 3 friction points or 2 shims escalates to /research-and-decide.
09Stuck protocol: more than 2 attempts without progress → state "Stuck: [task], [attempt N], [blocker]" and switch approach; after 2 switches, escalate.
10Post-incident discipline: a P0/P1 needs a root-cause artifact before the next task; the same cause twice in 14 days forces an ADR.
